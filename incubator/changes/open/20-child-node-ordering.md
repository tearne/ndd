# Child node ordering may carry meaning

**Kind:** idea
**Anchor:** m6x

The order in which a node lists its children may itself be significant, not incidental. Example that prompted this: under `Change-Management`, `Modes` currently precedes `Change Lifecycle`, but the lifecycle may be the more natural first read with modes as a qualifier on it — so the reverse order might be clearer. Open question whether ordering is a convention worth naming at all, and if so whether it's governed per-parent (the parent decides its children's order) rather than as a global rule. Unsure it matters; weigh before adopting.
