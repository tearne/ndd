# Tooling development

## Intent

The method deliberately rides generic markdown tooling today — see *Tooling (g8l)* — but a richer, purpose-built surface is anticipated and worth pursuing on its own: a browser-based viewer that maximises stakeholder engagement (rendering the map as navigable UI, letting non-devs read comfortably and flag or comment on nodes), plus a cross-map index. The markdown files stay the source of truth; the viewer is a read-optimised projection and a feedback-capture channel — it must not force devs off the CLI, and stays optional so CLI-only teams lose nothing. Fuller notes and the design tensions are in the retired `enhancement-discussion.md` (P3), kept in git history.
