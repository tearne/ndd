# Emergent style

**Change Style:** Formal

## Intent

Let a change deliver by working iteratively, each step informing the next, so that what gets built is found in the doing rather than specified first, and answering a question remains one kind of such work. Exploratory becomes Emergent to fit.

Raised as field process feedback (2026-10-14).

## Context

COD, the pre-release name of this method, had three modes (2026-05-04). *Explore* kept Formal's gates and delivered within the change; only its plan differed, as topics plus a *done-when* rather than tasks. *Wander* went from Intent straight to Build, wrote its Conclusion afterwards to capture the approach that emerged, could rename itself to where the work landed, and flagged topic drift. It came from field feedback sketching an agile, pairing-style cadence. Both survived the map rebuild as cadences (2026-08-14).

The Change Style rework (archived 2026-09-30) recast them. Wander became Trivial, reframed from "too fluid to plan" to "virtually no ambiguity", which left the fluid case without a home. Explore became Exploratory, with Focus as a conceptual question. The discussion behind it (`2026-09-29-forest.md`) left open "whether exploration later continues in place or produces another change", and held that "understanding, a decision or a handoff can be a complete outcome". The confining sentence in the current node closed that question with no recorded decision.

So this change restores dropped capability rather than adding new capability, and should consider whether Exploratory also takes up Wander's discover-as-you-go case.

If Exploratory delivers within itself, it may also want a companion folder for supporting material; today only Formal names one. The archive move is already general (Archiving, 2026-10-14), so only the folder's creation would need extending.
