# Requirement voice beyond Intent

**Change Style:** Vibe \
**Version:** 3.7.2-dev

## Intent

The guidance that a plan part is written in the voice of a requirement, such as "the application should…", should apply beyond the Intent to the other parts that state what a change must do or hold, so none of them reads as a description of what already exists.

## Bounds

Method map prose only: *Plan*, *Intent*, *Bounds* and *Focus*. Not *Change Specification*: its nodes describe the system as built, since they become the map.

## Context

Raised as an aside on 2026-11-11 while drafting 001's Bounds: 3.5.0 gave the requirement voice to *Intent* alone, and the Bounds of past Vibe changes are written in the present tense.

## Conclude

Rather than adding the rule to *Plan*, which would have reached 1,076 characters, a new *Requirement Voice* node under *Plan* owns it, beyond the four nodes the Bounds named; *Intent*, *Bounds* and *Focus* link to it. At the user's suggestion, it names the danger as describing what is to be as though it already were.
